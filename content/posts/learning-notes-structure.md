## 问题：笔记写完就再也不想看

常见的失败模式是"复制粘贴式笔记"：把文档整段搬过来，当时觉得收藏了，三个月后打开只剩一堆没有上下文的片段。原因通常不是记性差，而是笔记里缺了三样东西：**触发问题的场景、当时的错误预期、以及结论的适用边界**。

## 四段式结构

一个可复用的最小结构：

1. **一句话问题**：我到底想验证什么？
2. **最小可运行例子**：能删到不能再删的代码。
3. **预期 vs 实际**：我原本以为会怎样，实际发生了什么。
4. **边界与延伸**：什么时候这套结论不成立。

下面用一个 Python 切片的例子走一遍。

## 最小可运行例子

```python
items = [0, 1, 2, 3, 4]
print(items[::-1])        # [4, 3, 2, 1, 0]
print(items[1:4:2])       # [1, 3]
print(items[10:])         # []
```

问题很小：切片越界为什么不报错，而索引越界会报错？

```python
print(items[10])          # IndexError: list index out of range
```

## 预期 vs 实际

| 写法 | 预期（最初的想法） | 实际 | 结论 |
| --- | --- | --- | --- |
| `items[10]` | 返回 `None` | 抛 `IndexError` | 单元素取值必须命中 |
| `items[10:]` | 抛异常 | 返回 `[]` | 切片会把越界端点夹到序列长度 |
| `items[::-1]` | 倒序但含步长 1 | 完整倒序 | 负步长同时改变遍历方向与起止默认值 |

关键不在记住"切片宽容、索引严格"，而在理解二者的语义不同：**索引是在取一个确定的元素，切片是在描述一段区间**。区间为空是合法结果，元素不存在则不是。

## 边界与延伸

这条结论对内置 `list`、`str`、`tuple` 都成立，但对第三方容器不必然成立——它们可以自己实现 `__getitem__` 并决定如何处理 `slice` 对象。所以笔记最后值得写一句：

> 本结论适用于 CPython 内置序列类型；自定义序列的行为以 `__getitem__` 的实现为准。
